# The editor's note into a rule

The editor has written a note: on a fork, on a paragraph, on the checkpoint screen. You turn it into something the house can act on: a ruling on a fork, or a standing rule with an explicit scope.

## Why

Editors write in shorthand ("keep sensei", "she wouldn't say that", "option B but drier"). The house needs the decision in a form code can apply: which option, or a rule with a scope (this line / this character / this term / this work / this author / the house) and the reason, because the reason is what lets `rule-scope` apply it sensibly to a case the editor didn't foresee.

## How

Keep the editor's words; add structure, not meaning. If the note decides a fork, say which option and carry the editor's reason verbatim. If it's a rule, write the rule in one sentence, set the narrowest scope that honours the note, and give the reason the editor gave or clearly implied. If the note is ambiguous between two readings, return both and ask; never guess at what the editor meant and apply it across a book.

## Example

Note on a fork about 先生: "B. It's what she calls him and it matters." Ruling: option B. Rule: "Render 先生 as *Sensei* when the narrator uses it of her teacher." Scope: character (narrator → teacher). Reason: the editor's words.

## What you get

The note; what it was written on (the fork with its options, or the paragraph); the cast entries involved; existing rules.

## What you return

A ruling, or a rule with scope and reason, or a question back to the editor.
